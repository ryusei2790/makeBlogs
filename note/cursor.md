# ブログ記事執筆スタイルガイド

## ファイルの目的

このファイルは、ブログ記事執筆時のスタイルガイドです。一貫性のある文章スタイルを維持し、読者にとって読みやすく価値のある記事を作成するための指針として使用します。

## 文章の基本スタイル

### 文体
- **基本スタイル**: です・ます調を基本とする
- **親しみやすさ**: 「こんにちは！Ryuseiです。」のような親しみやすい挨拶から始める
- **読者との距離感**: 友達に話しかけるような親近感のある文体
- **専門性と親しみやすさのバランス**: 技術的な内容でも分かりやすく説明

### 段落の長さや構成の傾向
- **段落の長さ**: 3-5行程度の短めの段落を好む
- **見出しの活用**: 階層的な見出し（##、###）を多用して構造化
- **区切り線の使用**: `---` を使ってセクションを明確に分ける
- **箇条書きの活用**: 複雑な情報は箇条書きで整理

### よく使う表現やフレーズのリスト
- **導入**: 「こんにちは！Ryuseiです。」
- **目的説明**: 「今回は、〜について、自分用の備忘録を兼ねてまとめておこうと思います。」
- **気づきの表現**: 「〜だと気づきました。」
- **便利さの強調**: 「〜がとても便利です。」
- **次回予告**: 「次回は、〜していきます！」
- **締め**: 「引き続き、学んだことをブログとしてまとめていくので、よろしくお願いします！」

### 読者との距離感
- **親しみやすい**: 友達感覚で話しかける
- **共感を求める**: 「〜だと気づきました」で読者も同じ経験をしていることを前提
- **励まし**: 「〜してみてください」のような前向きな表現

### 具体例の使い方のパターン
- **コード例**: 実際のコードブロックを多用
- **表の活用**: 比較や一覧を表形式で整理
- **実体験**: 「実際に〜してみて」のような実体験ベースの説明
- **段階的説明**: Step1、Step2のように段階的に説明

## 執筆の基本方針

### 記事を書く目的（観察された傾向から推測）
- **学習記録**: 自分自身の学習過程を記録・整理
- **知識共有**: 学んだことを他の人にも役立つ形で共有
- **備忘録**: 後で振り返るための記録
- **技術解説**: 複雑な技術を分かりやすく解説

### 内容の選定基準
- **実践的**: 実際に試してみた内容を中心
- **初心者向け**: 専門用語は分かりやすく説明
- **段階的**: 基礎から応用まで段階的に説明
- **具体的**: 抽象的な概念は具体例で補完

### 情報開示のバランス
- **技術的詳細**: 必要な技術情報は詳しく説明
- **個人情報**: 必要最小限の個人情報のみ開示
- **エラー情報**: 実際に遭遇したエラーと解決策を共有
- **試行錯誤**: 失敗や試行錯誤の過程も正直に記録

### 避けている表現、好んで使う表現
**避けている表現**:
- 過度に専門的な用語（説明なしで使用）
- 否定的な表現
- 読者を見下すような表現

**好んで使う表現**:
- 「〜してみてください」（前向きな提案）
- 「〜がとても便利です」（価値の提示）
- 「〜だと気づきました」（発見の共有）
- 「〜していきます！」（継続性の表現）

### 執筆における大切にしている点
- **実体験に基づく具体的な内容を重視**: 実際に試してみたこと、経験したことを中心に記事を構成
- **読者が実践できる情報の提供**: 読者が実際に試せる具体的な手順やコードを必ず含める
- **誇張せず誠実な表現**: 過度な宣伝や誇張を避け、正直な体験談や感想を心がける
- **失敗や試行錯誤の共有**: 成功例だけでなく、失敗した経験や試行錯誤の過程も正直に記録
- **読者の立場に立った説明**: 初心者の視点を忘れず、分からない人にも分かるように説明
- **継続的な学習姿勢**: 完璧でなくても、学び続ける姿勢を大切にする
- **読者との対話感**: 一方的な情報発信ではなく、読者と対話しているような親しみやすさを保つ

## 記事の構成要素

### 典型的なタイトルの付け方
- **学習記録系**: 「【学習記録】〜」
- **技術解説系**: 「【完全ガイド】〜」
- **シリーズ系**: 「【第X回】〜」
- **実践系**: 「〜構想！〜を目指して」

### 導入部の書き方
1. **挨拶**: 「こんにちは！Ryuseiです。」
2. **今回の内容**: 「今回は、〜について〜」
3. **目的**: 「自分用の備忘録を兼ねてまとめておこうと思います」

### 本文の展開パターン
1. **背景・目的**: なぜその技術を学ぶのか
2. **基本概念**: 基礎知識の説明
3. **実践例**: 具体的なコードや手順
4. **試行錯誤**: 実際の開発過程での問題と解決
5. **まとめ**: 学んだことの整理
6. **次回予告**: 今後の予定

### 結びの特徴
- **学びの整理**: 今回学んだことを簡潔にまとめる
- **次回への期待**: 「次回は〜していきます！」
- **継続性の表明**: 「引き続き、学んだことをブログとしてまとめていくので、よろしくお願いします！」
- **読者への感謝**: 「最後までお読みいただき、ありがとうございました！」

## その他の特徴

### 記号・括弧の使い方
- **強調**: `**太字**` を多用して重要な部分を強調
- **コード**: `コード` でインラインコードを表現
- **見出し**: `#`、`##`、`###` で階層構造を作成
- **区切り**: `---` でセクションを分離

### 数字・期間の表記
- **回数**: 「第1回」「第2回」のような連番
- **期間**: 具体的な日付は避け、相対的な表現を使用
- **数値**: 技術的な数値は正確に記載

### 引用やコードブロックの使い方
- **コードブロック**: 言語指定付きで使用（例: ```html）
- **表**: 比較や一覧を表形式で整理
- **箇条書き**: 複数の項目を整理する際に使用
- **画像**: スクリーンショットや図解を多用

## 具体例

### 導入部の例
```
こんにちは！Ryuseiです。

今回は、個人プロフィールサイトの制作を通して学んだ **HTML/CSSの命名規則（特にBEM）** と **Emmet** の使い方について、自分用の備忘録を兼ねてまとめておこうと思います。
```

### 見出し構成の例
```
# 【学習記録】HTML/CSSの命名規則とEmmet活用メモ

## CSSの命名規則が必要な理由

## BEM（Block, Element, Modifier）の基本

## Emmetでコーディングを爆速化！

## Sassについても少し

## まとめ & 次回予告
```

### 技術解説の例
```
| 入力 | 出力/結果 |
| --- | --- |
| `!` + Tab | HTMLの雛形作成 |
| `h1.logo` | `<h1 class="logo"></h1>` |
| `ul>li*3` | 3つのリストを作成 |
```

### 結びの例
```
今回は、CSSの命名規則（BEM）とEmmetの使い方を学びました。次回は、今回の学びを活かして、自分のプロフィールページのクラス名や構造をリファクタリングしていきます！

引き続き、学んだことをブログとしてまとめていくので、よろしくお願いします！
```
