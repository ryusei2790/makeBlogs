【学習記録】ReactのuseStateでリストが増殖？ページネーション実装の落とし穴

こんにちは！Ryuseiです。

今日は友達から依頼されたアプリ開発で、Reactのページネーション実装中に遭遇したuseStateの問題について考えたことをまとめます。

背景・目的

最近、友達のアプリ開発を手伝うことになり、リストのページネーション機能を実装していました。ページネーションは、たくさんのデータを分割して表示するための定番機能です。今回は、ReactのuseStateを使ってリストの状態管理をしていたのですが、思わぬ落とし穴にハマりました。

問題の発生

ページを切り替えるたびに、useStateで管理しているリストがどんどん長くなってしまう現象が発生しました。具体的には、次のページや前のページに戻ると、useStateで保存していたリストに新しいデータが追加されるのは良いのですが、元々画面に描画されていたリストが消えずに残ってしまい、リストが増殖していく状態です。

試行錯誤・考察

正直、useStateの使い方はAIに任せっきりで、あまり深く理解していませんでした。カウンターを作るときは、次の数字にしっかり入れ替わるので、同じようにリストも「入れ替え」動作を意識すれば良いのでは？と気づきました。これなら、コードを大きく変えずに実装できそうです。

// イメージ例
const [items, setItems] = useState([]);

const handlePageChange = (newPageItems) => {
  setItems(newPageItems); // 追加ではなく、入れ替え！
};

本日の進捗と今後の課題

今日は考えただけで実装まではできませんでした。この問題は明日に持ち越しです。今後は、useStateの正しい使い方やリストの管理方法について、もう少し深く学んでいきたいと思います。

まとめ & 次回予告

今回は、ReactのuseStateでリストが増殖してしまうページネーション実装時の落とし穴について考察しました。次回は、実際にuseStateの挙動を検証し、リストの増殖問題を解決していく予定です。
